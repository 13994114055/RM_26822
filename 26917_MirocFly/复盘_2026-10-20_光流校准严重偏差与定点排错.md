# 复盘：2026-10-20 定点自激根因——光流校准严重偏差

> 目的：把四天（10-17 → 10-20）的弯路、证据、方法和结论留档，供后续复习与面试复盘。
> 结论先行：**POSHOLD 快速自激/过补偿的主因是 `opflow_scale` 严重偏小（1.133，实际约 4.4–4.7）**；同时叠加了两个独立配置漂移：`align_board_pitch=-42`（4.2° 假补偿，造成持续前倾）和活动 `control_profile=3`（默认手感，非 10-17 的 profile 1）。混控 `mmix` 是标准 QuadX，前电机没有坏。
> 当前仍保留：**2–3 cm/s 慢漂**，位于光流死区以下，属原理性限制；靠 I/P 只能减小，最终需要视觉/绝对参考。

## 0. 一句话版本

- `opflow_scale` 是“raw flow → deg/s”的**除数**；1.133 让估计速度/位置放大约 4 倍，POSHOLD 看到的速度远大于真实速度 → 反向补偿过量 → 自激/飞出去。
- 正确校准不是绕 yaw 自转，而是 **roll/pitch 倾斜 30s**（INAV `opflow.c` 累计的是 `bodyRate[X/Y]`）；yaw 校准得到的 5.19 **无效**。
- 真正的 tilt 校准值约 **4.4–4.73**；后来固定 **4.0** 做折中，POSHOLD 明显稳定（位置误差 12–57 cm，`navEPH` 3–20，无快速发散）。
- 4° 的 `align_board_pitch=-42` 是“用板对齐硬补静态偏置”的错误做法；它和 `control_profile=3` 一起造成“手感奇怪 + 持续前倾”。两者都已修正。
- 慢漂 2–3 cm/s 在光流死区以下（0.3m 高度死区约 26 cm/s），**不是 scale/PID 能修的**；这是纯光流无绝对参考的固有限制。

## 3. 光流校准原理（为什么会错、yaw 为什么无效）

### 3.1 scale 在链路中的位置

源码 `sensors/opflow.c:208`：

```c
const float integralToRateScaler =
    (opflow_scale > 0.01f) ? (1.0e6f / deltaTime) / opflow_scale : 0.0f;
opflow.flowRate[X] = rawFlow[X] * integralToRateScaler;
```

- `opflow_scale` 在**分母**：scale 越小 → 同样的 raw flow 换算出更大的 deg/s；
- 估计器再算 `v = (flowRate − bodyRate) × alt`；
- 所以 **scale 是反馈增益**：1.133 相对 4.5 约小 4× → 速度估计约大 4×。

### 3.2 INAV 校准代码在累计什么

`opflow.c:239-242`：

```c
opflowCalibrationBodyAcc += calc_length_pythagorean_2D(opflow.bodyRate[X], opflow.bodyRate[Y]);
opflowCalibrationFlowAcc += calc_length_pythagorean_2D(rawFlow[X], rawFlow[Y]) * invDt;
```

- `bodyRate[X/Y]` 来自陀螺的 **roll/pitch 角速度**，不是 yaw；
- 30s 后要求 `opflowCalibrationBodyAcc > 3600°`，再算
  `opflow_scale = flowAcc / bodyAcc`。

**所以正确动作是让机身绕水平轴 roll/pitch 倾斜**（Matek 文档：30s 内左右 roll、前后 pitch 倾斜 30–40°，光流始终看地面，不平移），不是原地 yaw 自转。

### 3.3 为什么 yaw 的 5.19 无效

- 纯 yaw 绕竖直轴转，陀螺 X/Y ≈ 0 → `bodyAcc` 不会累计到 3600°；
- 5.19 很可能是倾斜/抖动带出来的，不是有效 scale；
- 有效数据是 roll/pitch tilt 得到的 4.4/4.49/4.73。

### 3.4 回文式（back-and-forth）可以

- 代码累计的是**幅值**，方向不抵消；
- 没有连续一个方向转的条件时，可以左右/前后反复倾斜；
- 关键是：纯倾斜、不平移、q≥35、0.3–0.6m、纹理垫、30s、角速度 60–90°/s（死区 ~50°/s、饱和 ~400°/s）。

### 3.5 默认 10.5 不是目标

- 10.5 是通用默认值；MTF-02P/PMW3901 类常见 9–10；
- 本机 tilt 校准落在 4.4–4.73；4.0 是折中/实验值；
- **不要手设 10.5**，以 tilt 校准/known-tilt 为准。

## 6. 可复用的排错方法

### 6.1 先校验传感器，再调控制

- 传感器 scale 错 = 反馈增益错，现象和 PID/相位问题几乎一样；
- 先做：光流 scale（tilt）、align、q/高度/纹理、IMU 水平/A1、CoG；
- 再看：`navEPH`、`navPos/navTgtPos`、`navTgtVel/navVel`、`rcCommand/attitude`；
- 最后才动 `nav_mc_*` / `mc_*`。

### 6.2 看日志前先问五个问题

1. 这次是什么模式？`flightModeFlags=523`？`navState=6/7`？
2. 电池满吗？vbat 是否 ≥3.7V？
3. 有没有打杆？`rcData` 偏离 1500 多少？`navFlags` bit6 是否在调位置？
4. 目标点动了吗？`navTgtPos` 是否被杆移动？
5. 这段日志完整吗？是否 disarmed/被截断/desync 很大？

### 6.3 一次只改一个变量

- scale 固定后，再调 I/P/D/FF；
- 每步 `save` → 5s 干净 hold → 记录 → 保留/回退；
- 不同时改 I 和 P；不把“低电/打杆/目标移动”的日志当调参依据。

### 6.4 scale 与 PID 的判别

- scale 偏小：估计速度大 → 过补偿/振荡；
- scale 偏大：估计速度小 → 软/慢漂；
- PID 偏小：响应软、稳态误差；
- PID 偏大：过冲/振荡；
- 两者现象重叠，**必须用 known-tilt 或已知运动做独立参照**，不能只看手感。

## 9. 教训清单

1. **先校准传感器，再调 PID**；scale 错 = 增益错。
2. **读源码/文档确认校准轴**：yaw 5.19 无效；roll/pitch tilt 才对。
3. **P 项/坐标系自洽检验抓不到 scale**（共模增益）和 `align_board`（姿态基准）。
4. **`align_board_*` 不是配平/CoG 工具**；静态偏置用 A1 校准，不要用 -42 硬补。
5. **`control_profile` 要检查活动档**；profile 3 默认手感 ≠ profile 1 调参。
6. **`mmix` 标准并不等于前电机坏**；`motor[]` 是命令不是推力；先在 Motor 页/ESC 遥测确认。
7. **干净测试**：满电、不打杆、目标不动、模式位正确、5s；disarmed/截断/desync 大的日志不用。
8. **慢漂在死区以下**：2–3cm/s 不是 scale/PID 能修的；纯光流无绝对参考。
9. **一次只改一个变量**；改前备份 `diff all`；改后 `save`/重启/复读。
10. **安全**：bank 20、低空、软区、低速退出；POSHOLD 一振荡立刻切回；不要连拨 ch7。

## 附录 A：光流 scale 校准步骤（2026-10-20 修正版）

1. 拔桨；无人机固定在转盘/支架上；光流朝下；0.3–0.6m；纹理垫；q≥35。
2. Configurator → Calibration → Optical Flow（或 MSP2 `0x2032`）。
3. **绕 roll/pitch 倾斜**，不是 yaw；30s 内左右 roll + 前后 pitch，各 ±30–40°；角速度约 60–90°/s；不要平移、不要 yaw。
4. 30s 后 FC 算 `opflow_scale = flowAcc/bodyAcc` 并保存；读回确认。
5. 预期落在 4.4–4.7（本机 tilt 实测）；默认 10.5 不是目标；yaw 校准值无效。
6. 校准后做一次慢 yaw（±90°）看 `flow_damp mon` 的 `trans≈0`，检查 align；再做 5s POSHOLD。

## 附录 B：known-tilt（可选，用于复核 scale）

- 支架绕水平铰链倾斜；量 `r`（转轴→光流传感器）、`h`（传感器→垫）、`θ`；
- 传感器水平位移 `expected = r·sinθ`；速度 `expected_v ≈ r·ω`；
- 对比 `navPos`/`navVel`/`flow trans`；
- `ratio = measured/expected`；`scale_new = scale_current × ratio`；
- `ratio>1` → scale 偏小；`ratio<1` → scale 偏大；≈1 → scale 正常。
