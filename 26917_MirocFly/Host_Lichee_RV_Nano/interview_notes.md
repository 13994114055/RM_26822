## 1. 工具与库

### Q1. PIL 和 OpenCV 有什么区别？你项目里怎么用？
- **PIL/Pillow**：图像**处理**库（读写图、绘制、逐像素），轻量。
- **OpenCV**：计算机**视觉**框架（颜色空间、滤波、形态学、`findContours`、特征、DNN、视频流）；Python 绑定叫 **`cv2`**（不是独立库）。
- **本项目**：PC 上用 **PIL 生成合成图**（零依赖）、用 **`cv2` 写检测原型**；板端用 **opencv-mobile 5.0.0**（裁剪版）。
- **加分点**：PC 端 `opencv-python` 与板端 `opencv-mobile` **同大版本（5.0.0）**，原型 API 几乎可直搬板子。

### Q2. opencv-mobile 是什么？为什么嵌入式不用完整 OpenCV？
- 完整 OpenCV 体积大、依赖多；嵌入式用**裁剪版**，只保留需要的模块（如 core/imgproc/geometry），
  去掉 videoio/imgcodecs 以省空间和编译成本。
- **代价**：功能受限。例：**没有 imgcodecs** → 不能 `imwrite`，我们**手写 BMP**（B12）。

### Q3. 为什么 Python 原型 + C++ 部署两套？
Python 调参快、可视化好，用来**定算法与参数**；部署时换成 C++/opencv-mobile，**同一套算法两种实现**，兼顾开发效率与运行效率。

## 2. 传统 CV vs 深度学习

### Q4. 什么时候不上 AI、用传统 CV？
- **有强先验、目标形变可控** → 传统 CV 更快、可解释、零训练成本。装甲板的 LED 灯条（细长、成对、同色）就是典型。
- **无先验/形态复杂/类别多**（"不规则物体"、数字识别）→ 上学习型检测（YOLO）。
- **本项目策略**：阶段1 绿色 HSV 跑通闭环；阶段2 YOLO 找板 + HSV 判红蓝；**传统 CV 装甲板作为并行兜底/预研**。

### Q5. 传统 CV 的缺点？
对**光照/阈值敏感、泛化差**。所以工程上要：颜色空间选择 + 形状约束 + 几何配对 + **容忍度设计**（见第 4 节）。

---

## 3. 颜色分割

### Q6. 为什么用"通道差"而不是 HSV？（重点）
- **HSV**：H 分量在**低亮度/过曝**时漂移大；红色还跨越 0/179 需两段阈值。
- **通道差**：红 `R − max(G,B)`、蓝 `B − max(R,G)`，抽的是"**颜色纯度**"，对**乘性光照变化不敏感**，单段阈值、简单稳。
- **面试话术**："暗光/过曝下 HSV 的 H 不稳，我用通道差做颜色分割，再叠形状约束抑制误检。"

## 4. 装甲板几何（本项目的核心传统 CV）

### Q7. 装甲板长什么样、怎么找？
黑底 + 两侧**同色长条 LED**（红/蓝）+ 中间白数字。找法：
① 通道差分割 → ② 形态学去噪 → ③ `findContours`+`minAreaRect` 得灯条，按**长宽比/长度/面积**过滤 →
④ 同色**配对** → ⑤ 板中心。

### Q8. 为什么不能死卡"等高、对称"？
相机是**透视投影**：装甲板**偏航**时近侧灯条长、远侧短（**不等长**），间距变小（**梯形**）；俯仰/横滚使灯条倾斜。
→ 必须用**松弛约束**：长度比 ≤ ~2、y 差 ≤ ~0.4×灯条高、角度差 ≤ ~15°、间距给宽区间。

### Q9. 中心怎么估才稳？
不用"某条长边"，而是取每根灯条**两条短边的中点**连成**中轴**，再用两灯条中轴端点构成的**四边形对角线交点**。
- 好处：对**梯形**稳健，且不受 `boxPoints` 角点顺序（内/外边）影响。
- 实测量化：这样中心误差从 **~10px 降到 0.34px**。

### Q10. 你怎么证明检测是"准"的？
- **合成图带真值**（板中心/四角已知）→ 自动算**召回/精确/中心误差**：合成集 **召回 100% / 精确 100% / 中心 0.34px**。
- 诚实说明：合成是**干净可控**数据，分数偏高属预期；真实相机（光照/模糊/杂波）要**上板再验**（S2）。
- **面试加分**："我用真值驱动做可量化验证，而不是肉眼看着像。"

## 5. 嵌入式/系统（体现动手能力，详见 `difficulty_and_method.md`）
- **交叉编译头/库必须对齐板子版本**：中间件版本混用 → 取帧**全黑**（B7）。
- **DSO 符号可见性**：板载 `.so` 未声明依赖时 musl 不自动加载 → 显式链接（`-lgdc`、`board_libs`，B13）。
- **隐藏原子符号** → `-lgcc_s`；**传递依赖版本错配**（`libtdl_ex` 拉 libcurl）→ 不链它（B13）。
- **ION 内存泄漏**：相机/推理反复跑会耗尽 carveout → SIGTERM 收尾、必要时 reboot（B4）。
- **量化是门槛**：TPU-MLIR docker + 校准集 + 导出脚本（B15）。
