# 验证手册：模型 + 整条软件链路

> 目标：**判断"模型能不能检出"和"链路通不通"**，而不是凭感觉。
> 三步各自独立，哪步不过就停在哪步排查。

## 第 1 步：链路体检（不需要绿色物体）

```bash
ssh root@192.168.1.165 '
  killall vision_rtsp vision_node rtsp_grab 2>/dev/null; sleep 3
  export LD_LIBRARY_PATH=/mnt/system/usr/lib:/mnt/system/usr/lib/3rd:/mnt/system/lib:/usr/bin/lib:/maixapp/lib:/mnt/system/opt/cvitek_tpu_sdk/lib
  cd /root/mirocfly
  setsid ./vision_rtsp best_cv181x_int8_sym.cvimodel 1280 720 127.0.0.1 7788 >/tmp/vr.log 2>&1 &
  sleep 5
  ./vif_stat 7788 15
'
```

### 合格判据

| 指标 | 合格 | 不合格说明 |
|---|---|---|
| 平均帧率 | **≥ 15 fps** | <10：模型太慢/CPU 被占 |
| 坏包(大小错) | **0** | 接口版本不匹配 |
| 坏包(magic错) | **0** | 发的是别的协议 |
| 断流(>300ms) | **≤ 2 次/15s** | WiFi 丢包或程序卡 |
| n 分布 | 全部 `n=0` 或出现 `n=1` | 出现 `n>8` 说明越界（不应发生）|

> 这一步过了 = **"视觉 → UDP → 控制端"的管道是通的**。

## 第 2 步：模型检出（需要绿色物体）

保持 `vision_rtsp` 在跑，**拿一个绿色物体**（≥10cm）放在相机前 **0.5–2m**：

```bash
ssh root@192.168.1.165 'cd /root/mirocfly && ./vif_stat 7788 15'
```

### 合格判据

| 指标 | 合格 | 说明 |
|---|---|---|
| 目标帧占比 | **> 70%**（物体静止时） | 低于 30%：模型弱或阈值高 |
| 平均置信度 | **> 0.6** | 0.5–0.6：临界；<0.5 说明量化损失大 |
| dx 范围 | 随物体左右移动而变化 | 不变 = 坐标算错 |
| dy 范围 | 随物体上下移动而变化 | 不变 = 坐标算错 |

### 同时看画面（带框）

```bash
# 你电脑上
ffplay -rtsp_transport tcp rtsp://192.168.1.165/h264
```

**看到框 = 模型 + 坐标 + 画框三件事全对**。

## 第 3 步：控制端响应（不需要飞控）

```bash
ssh root@192.168.1.165 '
  cd /root
  MIROCFLY_SIM_AUX="1000,1500,1500,2000" MIROCFLY_SIM_ARMED=1 MIROCFLY_SIM_ALT=100 \
    ./vision_bridge.rv --no-fc --force-auth 2>&1 | grep -E "FSM|ALIGN|TRACK|SEARCH" | head -20
'
```

### 合格判据

| 现象 | 合格 |
|---|---|
| 无目标 | `SEARCH`，`out yaw=1600`（自转） |
| 有目标 | `TRACK_IDLE → ALIGN` |
| 物体在右 | `out` 第三个值 > 1500 |
| 物体居中 | `out ≈ (1500,1500,1500)` |

## 常见失败与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| `vif_stat` 收不到任何帧 | 端口不一致 / 视觉程序没起 | `nc -ul 7788` 看有没有数据 |
| 帧率极低（<5） | 模型推理慢 / CPU 抢占 | 降分辨率到 640×360 试 |
| 目标帧占比低但画面里明明有绿色 | 置信度阈值 0.5 偏高 | 改 `TDL_SetModelThreshold` 到 0.35 |
| 有目标但 conf 很低（~0.3） | 量化精度不足 | 用更多实拍图重做校准（20–50 张） |
| 画框位置偏 | letterbox 映射 | 检查 draw 与 detect 是否同一坐标空间 |

## 结论怎么下

```
第 1 步过 + 第 2 步过 + 第 3 步过
   → 链路与模型都可用，可以进入"接飞控"阶段

第 1 步过、第 2 步不过
   → 链路没问题，是模型/阈值/校准的问题

第 1 步不过
   → 先修链路，模型的事后面再说
```
