# 2026-10-15_21_flow_quality（实验：阶段 0 光流质量实测）

**目的**：阶段 0 —— 用只读 `paradigm mon` 实测 MTF-02P 的光流质量 `q`，弄清它受**地面材质 / 高度 / 光照**的影响，判定光流能否越过 INAV 的 VALID 门限（即“光流是否可用”）。

## 判定口径（源码核实，关键）

- 上位机 `mon` 显示的 `q` = 模块 raw quality 经 `sensors/opflow_msp.c` 的 `×100/255` 换算 → **0–100 标度**。
- INAV `sensors/opflow.c` 门限：`OPFLOW_SQUAL_THRESHOLD_HIGH = 35`（**q≥35 才进入 VALID**）、`OPFLOW_SQUAL_THRESHOLD_LOW = 10`（**q≤10 才退出**，滞回）。
- **q<35 时 flowRate 被强制置 0、光流不被采用** → “上电时 q 能否越过 35”是可用性关键；一旦越过，只要 q>10 就能保持。

## 方法

- 板上只读运行 `paradigm mon /dev/ttyS0 230400`（不发任何控制），单次 15–45s；`mon` 不占相机。
- 每次只改变一个外部条件（支撑/手举、地面材质、光照、高度）。
- 原始日志：`logs/`（文件名标注条件）。

## 结果（关键对照）

| 组 | 条件 | 高度 | q（p50/范围） | ≥35 占比 |
|---|---|---|---|---|
| H | 固定架 + **光滑地面** | 52cm | 21（20–22） | **0%** |
| B | 固定架 + 纹理垫 | 29cm | 34（33–38） | 40–50% |
| I | 固定架 + **鼠标垫** | 35cm | **39（37–41）** | **99%** |
| D | 固定架 + 纹理垫 + **强光直射** | 29cm | 21（19–23） | 0%（**反而更差**） |
| F/G | 手举 + 鼠标垫 | 49–61cm | 44–53 | 100%（站稳后） |
| J | **起飞姿态**（机体坐鼠标垫上） | **1cm** | **25.5–26.8** | **0%**（冷启动窗口） |
| A1/A2 | 手举 + 未知面（早期） | 41–45cm | 50 / 20 | 不稳定 |

**决定性对照**（同架、同静止、**只换下方材质**）：光滑 `q≈21` → 鼠标垫 `q≈39`。

## 结论

1. **表面纹理主导**：光滑地面在 38 / 50 / 70cm 均 ≈20–24，**永远低于门限 35**（抬高救不了光滑面）。
2. **有纹理面（鼠标垫即可）稳定 ≥35**（37–53）→ **光流可启用**；29cm 的纹理垫也可（33–38，会在数秒内越过门限）。
3. **强光直射反而变差**（疑高光过曝）；`q` 随运行时间**缓慢上升**（上电后等数秒更稳）。
4. **运动响应**：手移主要由 **fY** 轴拾取（86→347，量化步进≈43），`opflow_scale` 尚未标定（后续实飞标定）。

## 操作性结论

> 测试/飞行区铺**纹理地垫（鼠标垫即可）** + 飞行高度 **0.3–0.6m** + 上电后**稍等数秒**再起飞 → 满足 POSHOLD 的“光流健康”前提（仍受**无 GPS 解锁拦截**限制，见 `Low_MCU/new_mcu/AGENT_GUIDE.md` §6-19）。

## 起飞窗口（重要，2026-10-15 讨论 + 实测）——不是缺陷，有明确对策

- **起飞姿态实测（J 组，机体坐在鼠标垫上，alt=1cm）**：`q = 25.5–26.8`（稳定），**达标率 0%** → 冷启动时 XY 光流不激活（预期）。
- **爬升越门限的高度**：综合实测 `1cm→26.5 / 20cm→34 / 29cm→34–38 / 35cm→39 / 58cm→50` → **约 25–30cm 以上即可越过 35**（光滑地面则永远不过，见上）。
- **只影响“冷启动到第一次爬升”**：`q=26.5 > 10`，而 INAV 退出 VALID 需 `q≤10` → **一旦某次飞行进入 VALID，之后落地休息也保持有效**（滞回）。多次起降只有第一次存在窗口。
- **起飞不需要光流**：起飞/爬升由 **ALTHOLD**（测距 Z 分支，~1–200cm 有效）+ ANGLE 姿态完成。
- **光流无效时是安全的**：FC 将 XY 速度衰减为 0，`canActivatePosHoldMode()` 不满足 → **POSHOLD 不会激活**，不累积漂移。
- **操作规则**：`ANGLE+ALTHOLD 起飞 → 爬到 0.3–0.5m → 等 1–2s → 再切 POSHOLD`。
- **上位机自动门控（推荐）**：`mon` 已能读 `q`（本实验验证）→ 任务状态机加“**q≥35 才允许切 POSHOLD**”，全自动无需人工。
- 可选硬件：起落架垫高使模块落地即 >8–10cm（只影响“起飞那几秒”，不影响方案）。

## 复现命令

```bash
# 板上只读测量（~16s）
ssh root@10.222.2.1 'cd /root/mirocfly && (LD_LIBRARY_PATH=/mnt/system/usr/lib:/mnt/system/usr/lib/3rd ./paradigm mon /dev/ttyS0 230400 >/tmp/mon.log 2>&1 &); sleep 16; killall paradigm; cat /tmp/mon.log' > mon.log
# 统计 q（本机）
grep -o 'q= *[0-9]*' mon.log | grep -o '[0-9]*' | sort -n | \
  awk '{a[NR]=$1;s+=$1;if($1>=35)g++} END{printf "n=%d min=%d p50=%d max=%d mean=%.1f >=35=%.0f%%\n",NR,a[1],a[int((NR+1)/2)],a[NR],s/NR,100*g/NR}'
```

## 注意

- `mon` 只读、不占相机；`ttyS0` 与其它链路程序（takeover/flow_damp 等）互斥。
- 停止用 **SIGTERM**（`killall paradigm`），别 `kill -9`。
- 附带发现：ch6/ch8 中位即 1500，而 FC 接管区间是 `>1300` → **中位也算“接管激活”**（`ovr=1`）；单开关方案需用两段开关或把区间收到 `[1700,2100)`。
